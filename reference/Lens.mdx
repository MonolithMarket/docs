# Lens Contract

The Lens contract provides read-only access to protocol data and analytics for the Monolith lending protocol.

<ParamField path="contracts/Lens.sol" type="string">
  View contract for protocol data access
</ParamField>

## Constructor

```solidity
constructor()
```

Initializes the Lens contract with no parameters.

## User Position Functions

### getCollateralOf

```solidity
function getCollateralOf(Lender _lender, address borrower) public view returns (uint256 collateralAmount)
```

Returns the collateral balance of a borrower in a specific lender.

**Parameters:**
- `_lender`: Address of the lender contract
- `borrower`: Address of the borrower

**Returns:**
- `collateralAmount`: Amount of collateral deposited (in wei)

**Note:** This function accesses the lender's internal collateral balance mapping.

## Pool Analytics Functions

### getTotalValueLocked

```solidity
function getTotalValueLocked(Lender _lender) public view returns (uint256 tvl)
```

Calculates the total value locked in a lender pool.

**Parameters:**
- `_lender`: Address of the lender contract

**Returns:**
- `tvl`: Total value locked in USD (scaled by price feed decimals)

**Calculation:**
```solidity
collateralValue = totalCollateral * collateralPrice
borrowedValue = totalDebt * coinPrice
tvl = collateralValue + borrowedValue
```

### getUtilizationRate

```solidity
function getUtilizationRate(Lender _lender) public view returns (uint256 utilization)
```

Calculates the current utilization rate of a lender pool.

**Parameters:**
- `_lender`: Address of the lender contract

**Returns:**
- `utilization`: Utilization rate in wad (0-1e18)

**Formula:**
```solidity
cash = collateralBalance - totalDebt
if (cash + totalDebt == 0) return 0;
return totalDebt * 1e18 / (cash + totalDebt);
```

**Returns:**
- `threshold`: Liquidation threshold in wad (e.g., 0.85e18 = 85%)

---

### getHealthFactor

```solidity
function getHealthFactor(Lender _lender, address borrower) public view returns (uint256 healthFactor)
```

Calculates the health factor for a borrower's position.

**Parameters:**
- `_lender`: Address of the lender contract
- `borrower`: Address of the borrower

**Returns:**
- `healthFactor`: Health factor in wad (values > 1e18 are healthy)

**Calculation:**
```solidity
collateralValue = collateralAmount * collateralPrice
debtValue = debtAmount * coinPrice
if (debtValue == 0) return type(uint256).max;
healthFactor = collateralValue * liquidationThreshold / debtValue;
```

### getMaxBorrowAmount

```solidity
function getMaxBorrowAmount(Lender _lender, address borrower) public view returns (uint256 maxBorrow)
```

Calculates the maximum amount a borrower can borrow given their current collateral.

**Parameters:**
- `_lender`: Address of the lender contract
- `borrower`: Address of the borrower

**Returns:**
- `maxBorrow`: Maximum borrowable amount in wei

**Calculation:**
```solidity
collateralValue = collateralAmount * collateralPrice
maxBorrow = collateralValue * collateralFactor / coinPrice;
```

---

### getMaxWithdrawAmount

```solidity
function getMaxWithdrawAmount(Lender _lender, address borrower) public view returns (uint256 maxWithdraw)
```

Calculates the maximum amount a borrower can withdraw without becoming undercollateralized.

**Parameters:**
- `_lender`: Address of the lender contract
- `borrower`: Address of the borrower

**Returns:**
- `maxWithdraw`: Maximum withdrawable collateral amount

**Calculation:**
```solidity
requiredCollateral = debtAmount * coinPrice / collateralFactor;
maxWithdraw = collateralAmount - requiredCollateral;
```

## Integration Guidelines

### Frontend Integration
```javascript
// Get user position info
const position = await lens.getPositionInfo(lenderAddress, userAddress);

// Check if position is healthy
if (position.healthFactor < 1e18) {
    // Position is at risk of liquidation
    showWarning();
}
```

### Smart Contract Integration
```solidity
// Use Lens for view functions only
uint256 utilization = lens.getUtilizationRate(lenderAddress);
uint256 healthFactor = lens.getHealthFactor(lenderAddress, borrower);
```

### Best Practices
- Use Lens for all read operations to avoid state changes
- Cache results when possible to reduce gas costs
- Combine multiple calls in a single multicall when needed
- Handle stale price data appropriately

## Security Considerations

- Lens functions are view-only and cannot modify state
- Price data may be stale; always check `updatedAt` timestamps
- Health factors are estimates and can change with price movements
- Use multicall patterns to batch multiple view calls efficiently
